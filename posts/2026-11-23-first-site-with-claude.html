Claude Codeでホームページを作って、公開後に失敗した話

このブログは、AIコーディングツールのClaude Codeと一緒に一から作りました。 ホームページ制作はほぼ初めてでしたが、思っていたよりずっと早く形になりました。 一方で、公開してから気づいた失敗もありました。作った流れと、その失敗から変えたことを記録しておきます。

言葉で伝えるだけで、サイトの形ができた

最初にやったのは、「どんなサイトにしたいか」を言葉でClaudeに伝えることです。

  • 個人の日記のようなブログにしたい
  • 静的なHTML/CSSだけで作りたい
  • 記事はあとから自分でも足していきたい

これだけで、トップページ・記事一覧・個別記事・プロフィールの4ページの構成ができました。 デザインも「ダークな雰囲気」「ナイタースキーや雪夜のイメージ」というふわっとした要望から、 配色・フォント・ヘッダー画像の使い方まで提案してくれました。

公開はGitHub Pagesで、独自ドメインはDNSのAレコードを設定してつなぎました。

公開してから気づいた失敗：commit履歴のメールアドレス

AIに任せきりにはせず、公開に関わる部分は一つずつ自分で確認するつもりでした。 それでも、公開後にcommit履歴へ個人のメールアドレスが残っていることに気づきました。 リポジトリを一時的に非公開に戻し、履歴を修正してから公開し直しました。

ファイルの中身は確認していても、「commitの作者情報」は見落としていました。 画面に表示されない場所にも、公開される情報があるということです。

なぜメールアドレスが残ると困るのか

公開リポジトリのcommit履歴は、誰でも読めます。メールアドレスを機械的に集めるプログラムもあります。 残っていると、次のようなことが起こりえます。

  • 迷惑メールやフィッシングが届きやすくなる（GitHubを装った偽の通知など）
  • 同じアドレスで登録している他のサービスやSNSと結びつけられ、身元をたどられるきっかけになる
  • メールアドレスがログインIDのサービスでは、パスワードリセットやなりすましの標的にされやすくなる

一度公開された履歴は、あとから修正しても、フォークやキャッシュに残った分までは消せません。 だからこそ、「公開してから直す」より「最初から出さない」仕組みが大事だと考えました。

自分のリポジトリでも確認できます

公開リポジトリのcommit履歴に残っているメールアドレスは、次のコマンドで一覧できます。

git log --all --format='%an <%ae>%n%cn <%ce>' | sort -u

自分の個人アドレス（xxx@users.noreply.github.com 以外）が出てきて、そのcommitを公開リポジトリにpush済みなら、誰でも見られる状態です。 GitHub上でも、commitのURLの末尾に .patch を付けると確認できます。

「気をつける」から「仕組みで守る」へ

この失敗のあと、気をつけるだけに頼るのはやめて、仕組みで守るようにしました。

  • commitの作者には、GitHubが用意するnoreplyのメールアドレスを使う
  • commitのたびに毎回自動で動くチェック（pre-commit hook）を入れる
    • 画像から位置情報などのメタデータを消す
    • アクセスキーなどの秘密情報が混ざっていたらcommitを止める
    • .env や鍵のファイルはcommitさせない
    • commitの作者メールアドレスがnoreply以外ならcommitを止める
  • GitHubの Settings → Emails で「Keep my email addresses private」と「Block command line pushes that expose my email」をオンにする（登録済みの自分のアドレスを含むpushを拒否してくれる）

hookを入れたあと、位置情報を書き込んだテスト画像でcommitして、位置情報が消えることを確かめました。 このリポジトリでは、AIがcommitしても自分がcommitしても同じチェックが動くので、「確認し忘れ」が起きにくくなります（意図して --no-verify で飛ばさない限り）。

これから：Markdownで書いて、pushしたら配信まで自動に

今は手書きのHTMLで記事を書いています。これから、次の順番で作り替える予定です。

  1. 作業場所をWSLに移し、pre-commit hookを入れる（済み）
  2. Astroを使い、新しい記事はMarkdownで書く。GitHub Actionsで自動ビルドする
  3. 配信をAWS（S3 + CloudFront）に移し、インフラはCDKで管理する
  4. 動的な機能は、必要になったらサーバーレスで足す

どの段階で止めても、ブログは動き続ける順番にしています。 作り替えの記録も、このブログに書いていくつもりです。

おわりに

ものづくりやデータ分析の仕事を経て、今はAI駆動開発を学んでいる身として、 このホームページ作りは「試しながら学ぶ」をそのままやったような体験でした。 AIで速く作れるぶん、何が公開されるかを確かめる仕組みを先に持っておくことが大事だと感じています。
